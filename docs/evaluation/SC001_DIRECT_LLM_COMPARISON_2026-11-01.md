# SC-001 직접 LLM 질의와 ai-legal-helper 비교 분석

- 검토일: 2026-11-01
- 직접 질의: [LegalChat 1bf6c817](http://127.0.0.1:3001/project/cmv56sw2u00063wm9ivtyrtdj/traces/1bf6c817-665f-4fd7-bfbf-4b3d6c6712e1?observation=0e896025-7390-48c2-8489-b9ed09ebf409)
- 동일 질문의 제품 실행: [LegalConsultation 6d8e258a](http://127.0.0.1:3001/project/cmv56sw2u00063wm9ivtyrtdj/traces/6d8e258a-a307-4991-a840-d0f940026bb0)
- 자료: 사용자가 첨부한 Pasted text.txt, 두 trace의 실제 generation 입력·출력과 노드 관측값, 현재 검증·분기 코드, 국가법령정보센터 조문.
- 작업 범위: 읽기·비교 분석 및 문서 작성. 제품 코드 수정, 서버 재시작, 새 모델 호출, 사건 데이터 변경은 하지 않았다.

## 1. 판단

**직접 LLM 답변을 더 유용하게 느끼는 데에는 충분한 이유가 있다. 같은 질문과 같은 11개 증거를 읽고 약 25초 만에 행동 지침을 제공했다. 제품은 약 8분을 사용했다. 다만 법률 정확성까지 직접 답변이 전부 우월하지는 않다.**

이번 제품 답변은 이전 문제 실행보다 개선되었다. 등록 사실을 상담의 전제로 사용하고, 후발 가압류와 임차인의 법적 우선순위를 구분하며, 임차권등기 완료 후 이사를 안내한다. 이 부분까지 실패했다고 평가하면 개선 방향을 잘못 잡는다.

반면 직접 답변에는 지정 퇴거일을 충분히 해석하지 않은 종료일 계산과 임대인 자력에 관한 단정이 있다. 직접 답변 전체를 정답으로 복사할 수는 없다. 제품이 지향해야 하는 것은 **직접 답변의 속도·질문 중심 설명을 유지하면서 중요한 오류만 실제로 줄이는 것**이다. 현재 실행은 그 추가 비용에 걸맞은 효용을 제공하지 못한다.

## 2. 비교 조건

두 실행의 현재 질문은 같다.

> 10월 15일 현재 보증금은 받지 못했고 점유와 주민등록을 유지합니다. 이사해야 한다면 어떤 순서로 진행해야 하나요? 사건 변화도 요약해 주세요.

직접 질의의 마지막 사용자 메시지에는 E01~E11의 본문 전체가 들어 있다. 제품의 출처 목록과 문서별로 대조한 결과 **11개 모두 공백·줄바꿈을 제외한 본문이 일치**했다. 제품의 최초 작성 입력에도 11개 문서명이 모두 들어 있다. 이번 차이를 “직접 LLM만 증거 원문을 읽었다”라고 설명할 수 없다.

양쪽에 기록된 모델명도 `gpt-5.4-2026-03-05`로 같다. 다만 시스템 프롬프트, 대화 이력, 법률 자료, 호출 설정과 실행 시각은 통제되지 않았다. 같은 모델명만으로 서비스 배포·부하·설정까지 같다고 단정할 수 없다.

직접 질의에는 짧은 시스템 메시지와 과거 대화가 포함된 총 21개 메시지가 전달됐다. 과거 임대차 상담과 미성년자 관련 질문 등도 포함되어 있어 완전히 독립된 단일 질문 실험은 아니다. trace에는 generation 1개가 기록되어 있고 별도의 검색·검증 observation은 없다. 관측되지 않은 외부 처리가 전혀 없었다는 뜻으로 확대하지 않는다.

첨부 텍스트와 trace 출력은 주요 논점·문구가 대응하지만 표시 형식 등이 달라 원문 완전 일치로 보고하지 않는다. 아래 수치와 구체 문장 평가는 trace 출력을 기준으로 한다.

## 4. 직접 답변이 더 좋게 읽히는 이유

1. **현재 행동부터 말한다.** 첫 문단에서 점유·주민등록 유지와 실제 임차권등기 완료 후 이동을 제시한다. 사용자가 다음 행동을 빠르게 찾을 수 있다.
2. **증거를 이야기로 연결한다.** 통지, 임대인 확인, 분할반환 제안, 임차인 거절, 가압류를 사건 흐름으로 설명한다. 문서에서 추출한 항목을 단순 나열하는 느낌이 적다.
3. **권고의 이유를 설명한다.** 신청·결정·등기 완료의 차이를 사용자의 이사 행동과 연결한다.
4. **본문의 출처 표기가 덜 방해된다.** 제품은 긴 파일명을 반복해 넣어 핵심 문장과 행동 순서를 끊는다. 직접 답변의 출처 검증 부족은 별도 문제지만 가독성 차이는 실제로 존재한다.
5. **대기 시간이 짧다.** 비슷한 분량의 답변을 수십 초와 수분 후 받는 경험은 크게 다르다.

다만 직접 답변도 위험 경고와 결론을 여러 절에서 반복한다. 4,879자로 제품보다 짧지 않다. 최종 제품 형식은 양쪽보다 간결해질 여지가 있다.

## 5. 직접 답변을 정답으로 삼을 수 없는 부분

### 5.1 지정 퇴거일을 검토하지 않은 7월 1일 종료 계산

E05의 문자는 4월 1일 발송됐지만 **9월 30일 이사와 그날 반환**을 요청한다. 직접 답변은 통지 도달 후 3개월이라는 일반 규칙으로 7월 1일경 종료 가능성이 크다고 설명하고, 내용증명에도 그 종료일 주장을 넣으라고 권한다.

묵시적 갱신 후 통지 도달 3개월 규정은 존재한다. 그러나 이 사건에서 명시한 장래 날짜가 의사표시에 어떤 의미인지 해석하지 않고 7월 1일을 실행 문서의 전제로 삼는 것은 근거가 부족하다. 이 검토 역시 조문만으로 반대 방향인 “무조건 9월 30일 종료”를 확정하지 않는다. **통지일, 지정일, 법적 효력 발생일을 구분하고 의사표시 해석을 설명해야 한다.** [주택임대차보호법 제6조의2](https://www.law.go.kr/법령/주택임대차보호법/제6조의2)

현재 질문의 기준일 10월 15일은 두 날짜 이후이므로 당장의 행동 방향과 종료일·지연손해금의 정확한 기산점은 구분할 수 있다. 불필요하게 7월 1일을 확정하는 대신, 통지와 지정일을 근거로 종료 요건을 검토하고 미반환에 대한 권리보전 절차를 안내해야 한다.

### 5.2 자금사정과 시세를 과도하게 단정

직접 답변에는 “임대인이 돈이 없음”, “돌려막기를 시도한 정황”, “전세 시세 하락”이라는 표현이 있다.

- E06·E07은 새 보증금에 의존하는 분할반환 제안과 대출 검토 발언을 담고 있다. 이를 근거로 지급 지연 가능성을 설명할 수 있지만 임대인의 전체 자산·자금 부재가 확정된 것은 아니다.
- E08은 주변 **호가**와 모집 실패 기록이며 실제 시세나 경매 낙찰 예상액을 확정할 수 없다고 명시한다. 임대인의 시세 하락 주장과 확인된 시장 사실을 구분해야 한다.
- “새 임차인의 보증금에 의존해 반환하려는 정황”처럼 증거가 보여주는 범위로 설명하는 것이 적절하다.

### 5.3 후발 가압류와 우선순위의 관계 설명 부족

직접 답변은 가압류와 유동성 위험을 강조하지만, 기존 임차인의 상대적 우선순위가 후발 가압류 때문에 뒤집히는지 명료하게 답하지 않는다. 동일 질문의 제품 답변은 이 구분을 더 잘한다.

대항요건과 확정일자를 갖춘 임차인의 후순위 권리자 등에 대한 우선변제 구조와, 임대인이 제때 현금을 지급할 능력, 최종 배당액은 별개다. E11이 확인하지 않은 조세·선행 권리까지 없다고 확대해서는 안 된다. [주택임대차보호법 제3조의2 제2항](https://www.law.go.kr/법령/주택임대차보호법/제3조의2)

### 5.4 행동 순서의 필수 조건과 병행 절차 혼동

직접 답변은 자료 정리 → 내용증명 → 소송 검토 → 임차권등기 순으로 배열한다. 읽는 사람이 소송을 먼저 해야 임차권등기를 신청할 수 있다고 이해할 수 있다.

법은 임대차 종료 후 보증금 미반환을 임차권등기명령 신청 요건으로 두며, 소송 선행을 그 요건으로 정하지 않는다. 이사에 필요한 권리보전 순서와 별도로 병행할 반환 청구 절차를 구분해야 한다. 실제 등기 완료 후 기존 권리를 유지한다는 직접 답변의 핵심 안내는 법문과 부합한다. [주택임대차보호법 제3조의3 제1항·제5항](https://www.law.go.kr/법령/주택임대차보호법/제3조의3)

## 6. 제품 실행에서 확인한 원인

### 6.1 증거는 읽었지만 최초 법령 검색이 빗나갔다

분류기는 `민법`을 선택했고 `retrieve_with_status`는 현재 질문 전체를 query로, category=`민법`, k=6으로 검색했다. 최초 작성에 전달한 법률 자료는 다음과 같다.

- 민법 제502조: 채권자변경으로 인한 경개
- 민법 제22조: 부재자의 재산의 관리
- 민법 제26조: 관리인의 담보제공, 보수
- 민법 제914조: 거소지정권
- 민법 제428조의2: 보증의 방식
- 민법 제865조: 다른 사유를 원인으로 하는 친생관계존부확인의 소

이 목록은 현재 질문에 필요한 주택임대차 권리보전 근거를 공급하지 못했다. 그 상태에서 약 55초 동안 답변을 작성하고 약 85초 동안 검증한 뒤에야 핵심 법령 누락이 확인됐다.

첫 검증 이후 확보된 조문은 주택임대차보호법 제3조·제3조의2·제3조의3·제6조다. **핵심 조문 확보를 긴 초안 작성 뒤의 복구 작업으로 미룬 구조**가 문제다. 임대차 종료 요건에 필요한 제6조의2는 최종 출처 목록에도 없었다.

벡터 검색이 이런 순위를 만든 정확한 원인이 임베딩, 색인 범위, query 구성, 필터 중 무엇인지는 이번 관측만으로 확정하지 않는다. 다만 검색 성공 상태나 k개 반환을 쟁점 근거 확보와 동일하게 취급하면 안 된다는 점은 확인된다.

### 6.2 출처 미확보를 허위 인용으로 분류해 전체 재작성

두 번째 검증 generation 자체는 PASS를 반환했다. 그러나 후처리는 `민법 제536조`가 출처 목록에 없다는 이유로 `CITATION_INVALID / REVISE`로 바꾸었다. 현재 `backend/src/ai_legal_helper/agents/verification.py:1461` 이후도 미확인 인용에 “허위 인용” 제거 지침을 부여하는 구조다.

실제로 민법 제536조는 존재한다. 이미 확보한 주택임대차보호법 제3조 제6항도 이를 준용한다고 적고 있다. 따라서 **존재하지 않는 인용**, **조문 본문 미확보**, **조문은 있지만 해당 사건에 적용되지 않는 인용**을 구별해야 한다. 검색되지 않았다는 사실만으로 허위로 부르는 것은 부정확하다. [민법 제536조](https://www.law.go.kr/법령/민법/제536조), [주택임대차보호법 제3조 제6항](https://www.law.go.kr/법령/주택임대차보호법/제3조)

이 지적 뒤 전체 재작성 48.826초와 전체 재검증 75.396초가 추가됐다. 합계 **124.222초**다. 참고 조문을 제거하는 대신 필요한 본문 확보와 해당 문장 적용 검토로 해결할 사안이다.

더구나 최종 답변은 주택임대차보호법 제3조 제6항의 매매·경매 상황 준용 구조를 일반 반환·인도 설명에 연결했다. 그 조항의 적용 범위와 현재 사실을 연결하는 설명은 여전히 약하다. **등록된 조문명으로 교체해 검증에 통과하는 것과 실질적으로 올바른 법적 근거를 제시하는 것은 다르다.**

### 6.3 정확성 검토보다 전체 산출물 반복 비용이 크다

현재 `backend/src/ai_legal_helper/workflows/document_consultation.py:240` 이후는 검증 결과에 따라 검색·재작성·최종화로 분기한다. 이번 실행은 작성 3회와 검증 3회를 수행했다. 검증 출력만 합계 15,006토큰으로, 사용자에게 보여주는 최종 답변보다 훨씬 큰 내부 산출물을 반복 생성했다.

최초 작성도 질문의 큰 방향과 사건 흐름을 이미 답했다. 따라서 이번 개선 우선순위는 작성 지침을 계속 늘리는 것보다 **적절한 법률 자료를 처음부터 공급하고, 문제 문장 중심으로 검증·수정하는 것**이다.

### 6.4 제품 최종 답변에도 남은 설명 문제

- 미반환 상태에서 이사해야 한다는 질문에 대해 처음에는 “보증금 전액 반환 확인 → 인도 → 전출”을 강조한다. 필요한 대안인 임차권등기 경로를 첫 문단의 중심에 두는 편이 더 직접적이다.

- 임차권등기는 종료 후 신청 가능하다고 설명하지만, 이 사건의 통지와 지정일에 비추어 현재 종료 요건을 어떻게 보는지 충분히 적용하지 않는다. 직접 답변처럼 7월 1일을 성급히 정하지 않은 점은 좋으나 조건만 적고 사건 적용을 생략하는 것도 부족하다.

## 7. 개발 방향에 대한 권고

기존 [품질·지연 개선 지시서](../development/CONSULTATION_QUALITY_LATENCY_DEVELOPMENT_DIRECTIVE_2026-11-01.md)에 대해 이번 관측은 다음 우선순위를 뒷받침한다. 여기서 구현을 진행한 것은 아니다.

1. **같은 원문을 읽는 단일 작성 흐름을 비교 기준으로 고정한다.** 직접 답변 전체를 정답으로 지정하지 않고 질문 충족, 증거 연결, 오류, 응답 시간의 기준으로 사용한다. 이번 비교에서는 11개 증거가 이미 제공되므로 증거 검색 확대를 우선 과제로 삼지 않는다.
2. **핵심 쟁점의 법령을 작성 전에 확보한다.** 이사·미반환·권리보전이면 종료 요건과 임차권등기 효과가 우선이다. 무관한 민법 검색 결과를 채우고 나중에 복구하는 순서를 바꾼다. 자동 조회 승인 정책은 별도로 정하되 실제 처리 시간 목표와 승인 대기는 분리한다.
3. **검증을 중요한 오류에 집중시킨다.** 지정일과 통지일 혼동, 지급 방향·금액, 후발 가압류와 우선순위, 등기 신청과 완료의 차이, 법률 적용 범위를 우선 검사한다. 문장별 장문의 평가 결과를 반복 출력하는 비용을 줄인다.
4. **수정 범위를 오류 범위에 맞춘다.** 부족한 조문 하나는 해당 본문 확보와 관련 결론 재검토로 해결한다. 인용 번호만 기계적으로 바꿔 의미 검증을 생략해서도 안 된다. 사실·결론이 바뀌는 경우에만 영향을 받는 범위의 작성·검증을 확장한다.
5. **답변은 현재 질문을 중심으로 구성한다.** 첫 문단의 행동, 짧은 사건 변화, 실제 결론을 바꾸는 확인 사항 순으로 제공한다. 출처는 짧은 표시와 펼침 상세로 연결하고 근거 추적 가능성은 유지한다.
6. **호출·시간 예산을 모든 분기에 적용한다.** 검색 후 작성, 수정, 제한 답변도 같은 예산에 포함한다. 기존 지시서의 지연 목표는 목표일 뿐 달성된 수치로 표시하지 않는다.

현재 자료는 모델 변경을 먼저 해야 한다는 근거보다 검색·검증 흐름을 줄여야 한다는 근거가 강하다. 모델 변경 효과를 이 단일 실행 쌍에서 추정할 수는 없다.

추가 대량 테스트 전에 이번 동일 질문 쌍을 고정 사례로 사용하면 된다. 개선 전후에 날짜 해석, 임차권등기 완료 조건, 후순위 관계, 미확보 인용 처리와 지연이 어떻게 달라졌는지를 먼저 확인한다. 현재 직접 답변과 제품 답변 모두 완성된 POC 정답으로 승인하지 않는다.
