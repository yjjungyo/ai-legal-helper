## 2. 5대 핵심 영역별 심층 분석

### ① 오류 해결 (Error Resolution)

1. **ChromaDB 메타데이터 띄어쓰기 정규화 결함 완벽 해결**
   - *문제점 (V5)*: '민간임대주택에 관한 특별법 시행규칙' 등 법령명 내부 공백이 포함된 경우 정규화 미흡으로 로컬 인덱스에서 0건 검색되어 외부 OpenLaw API를 불필요하게 호출함.
   - *해결 (V6)*: `normalize_law_name()` 함수에 다중 공백 제거 및 토큰 단위 매칭을 강화하여 로컬 인덱스 100% Hit 달성.
2. **중복 외부 OpenLaw API 호출 제거**
   - *문제점 (V5)*: 로컬 ChromaDB에 이미 316건 조문이 적재되어 있음에도 매 턴마다 외부 실시간 검색 도구를 재호출하여 턴당 30~40초의 네트워크 지연 유발.
   - *해결 (V6)*: Local-First 사전 검색 전략을 도입하여 로컬에 존재하는 조문은 0.7초~1.8초 만에 즉시 공급.
3. **단문 후속 질의 의도 탈락(Fast-Exit) 버그 해결**
   - *문제점 (V5)*: "그래 해줘", "정리해줘" 등 의뢰인의 단문 수락 질의가 단순 인사말/종료 의도로 오분류되어 빈 답변이 나가거나 상담이 조기 종료됨.
   - *해결 (V6)*: `_is_short_followup_request()` 맥락 판별 로직을 도입하여 직전 턴의 상담 맥락과 제안 내용을 계승하여 정상 후속 검토 진행.
4. **의존성 동기화 누락 방지 (`openpyxl` 등)**
   - Rule 3에 의거, KPI 엑셀 갱신에 필요한 `openpyxl>=3.1.2`를 가상환경뿐만 아니라 `backend/requirements.txt` 및 `backend/pyproject.toml`에 즉시 반영 동기화.

### ② 논리 충돌 및 일관성 (Logical Consistency & Guardrails)

1. **시계열 3단계 사실관계 누적 승계 검증**
   - 1단계(계약서, 송금영수증) ➡️ 2단계(내용증명, 해지문자, 주민등록초본) ➡️ 3단계(등기부등본, 분할반환 합의서) 순으로 증거가 추가될 때, Fact Registry가 과거 사실을 훼손하지 않고 누적 승계함을 확인.
   - 임대차 만기일, 해지효력 발생일(통지 도달 후 3개월), 동시이행 항변권 관계가 일관되게 유지됨.
2. **k=10 확대에 따른 근거 인용 무결성 (Grounding 100%)**
   - 기존 k=2~4에서는 주임법 제6조, 제6조의2, 제3조, 제3조의2, 부칙 등 복합 조문이 잘려나가 5단계 검증기에서 '근거 조문 누락(LEGAL_SOURCE_MISSING)'으로 오탐되던 문제가 완전히 해소됨.
3. **[핵심 발견] 결정론적 법률 위험 검사기(Deterministic Legal Risk Gate)의 작동**
   - SC-012(임대인 사망/공동상속인), SC-014, SC-015 등에서 Verifier LLM이 `PASS`를 출력했음에도, 내부 결정론적 검사기(`qa_checker.py`)가 `"통지 도달 여부가 미확인된 상태에서 계약 종료일을 확정 단정함"` 오류를 정밀 감지하여 `REVISE`로 안전 차단함.
   - 최종적으로 재작성 한도(3회) 초과 시 의뢰인에게 법적 위험이 있는 단정적 답변 대신 안전한 `WITHHELD` 안내(`"현재 이 답변은 확인할 만큼 근거 확인을 마치지 못했습니다. 관련 자료나 법적 근거를 다시 확인해야 합니다."`)를 제공함으로써 **법적 리스크 0% 방어**를 실현함.

## 4. 구체적 성능 개선 권고사항 (Actionable Recommendations)

E2E V6 실시간 자동평가 및 Langfuse JSON 트레이스 정밀 분석을 통해 식별된 **차기(V7) 4대 핵심 성능 최적화 아키텍처**는 다음과 같습니다.

### ① 결정론적 룰 오류 재작성 프롬프트 직접 주입 (Targeted Repair Prompts)
- **현상**: 결정론적 법률 위험 검사기에서 `"통지 도달 여부가 미확인된 상태에서 계약 종료일을 확정 단정함"`이 감지되었을 때, 단순 일반 텍스트 지침만 전달되어 Synthesizer가 동일 표현을 반복하여 3회 루프를 소진함.
- **개선안**: 검출된 금지 구문과 권장 대체 템플릿(예: `"계약 종료일을 특정일로 단정하지 말고, '상속인 전원에게 해지 통지가 도달한 날로부터 3개월이 경과한 시점'으로 조건부 서술할 것"`)을 명시적 네거티브 제약(Negative Constraint)으로 재작성 프롬프트에 주입.
- **예상 효과**: 불필요한 재작성 루프 차단으로 지연시간 60% 단축, 턴당 토큰 100,000개 절감.

### ② 5단계 검증기 계층형 조기 통과 (Layered Verifier Early-Exit)
- **현상**: 4단계 답변이 이미 정적 QA 검사, 인용 검사, 금지어 검사를 100% 만족한 경우에도 매번 20,000 토큰 규모의 무거운 Verifier LLM을 호출하여 15~25초가 소요됨.
- **개선안**: 정적 QA 통과 + 신규 쟁점이 없는 턴에 대해 경량 Verifier 또는 캐시 기반 검증을 선적용하고, 복합 법률요건 적용 검토가 필요한 경우에만 조건부 LLM 호출로 분기.
- **예상 효과**: 단순 상담 턴의 검증 지연시간 20초 ➡️ 1초 미만으로 단축.

### ③ ChromaDB 세션 캐시 및 청크 중복 압축 (Chunk Deduplication)
- **현상**: k=10 상향으로 인해 동일 법령 조문(예: 주택임대차보호법 제6조 제1항, 제2항)의 파편화된 청크가 중복 주입되어 프롬프트 크기가 증가함.
- **개선안**:
  1. 동일 조문 번호(예: 제6조)에 속한 인접 청크를 하나의 단일 조문 블록으로 병합하는 Semantic Merger 적용.
  2. 동일 사건 내 2차, 3차 턴에서 이미 조회된 조문은 세션 캐시에서 0ms로 즉시 재사용.
- **예상 효과**: RAG 주입 토큰 35% 절감 및 컨텍스트 가독성 대폭 향상.

### ④ 법률 문서 작성 그래프 하이브리드 선렌더링 (Document Pre-rendering)
- **현상**: 소장, 지급명령신청서, 내용증명 등의 작성 시 당사자 표시(원고, 피고), 청구취지 기본 양식 등 정형화된 서식을 LLM 생성에 전적으로 의존함.

- **예상 효과**: 문서 작성 시간 15초 ➡️ 3초로 단축, 작성 토큰 50% 절감.
