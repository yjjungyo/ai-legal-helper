## 2. 공식 법령을 확보해 놓고 검증 LLM에는 전달하지 않았다

법령 검색 승인 후의 `execute_statute_search_node` 출력에는 다음이 있다.

- 전체 출처 44개.
- 이 중 `OFFICIAL_STATUTE_SEARCH` 법령 출처 20개.
- 주택임대차보호법 제6조, 제6조의2, 제2조, 제3조, 제3조의2 등의 원문 content가 실제로 존재한다.
- 두 번째 `verification_node` 출력에도 44개·공식 검색 20개가 유지된다.

그러나 `agents/verification.py`의 `run_verification()`은 입력 목록의 **앞 6개만** LLM 프롬프트에 넣는다. trace에 저장된 실제 GENERATION 입력에서 직접 확인한 출처 목록은 다음과 같다.

1. 민법 제639조 벡터 검색 청크.
2. 민법 제312조 벡터 검색 청크.
3. 사건 증거 GRAPH 출처 4개.

주택임대차보호법 제6조·제6조의2 공식 검색 출처는 이 프롬프트 구간에 없다. 뒤에 추가된 공식 법령 20개가 통째로 제외되었다.

그 결과 검증기는 ‘검색된 출처 목록에는 주택임대차보호법 원문이 없다’고 판정한다. 제6조·제6조의2 등에 대해서는 실제 검색 실패가 아니라 **검증 입력에서의 누락**이다. 다만 모든 필요한 조문이 확보된 것은 아니므로, 이 결과를 공식 검색만 하면 무조건 PASS라는 뜻으로 해석해서는 안 된다.

관련 observation:

- 공식 검색 병합: `18926772-ed9b-4f82-b7be-20af93c367fb`
- 재개 후 검증 노드: `b1423818-45db-4b45-9c65-bcfa785388dc`
- 실제 검증 GENERATION 입력: `67b09597-8a02-43aa-8887-3516a89450ea`

결정적 인용 감사는 전체 출처를 사용하므로 인용 존재율 1.0을 기록하지만, LLM은 그보다 훨씬 적은 출처를 보고 판단한다. 두 검사가 서로 다른 입력 집합을 사용하는 상태다.

## 3. 최종 답변이 질문의 핵심과 갱신 경위를 잃었다

법령 검색 후 재분석 초안에는 묵시적 갱신 가능성, 갱신 시 기간, 해지 통지와 도달에 따른 효력, E04의 진술·원본 확인 한계가 포함되어 있었다. 초안에는 통지 문구와 지정 퇴거일을 더 검토해야 하는 부분도 있으므로 그대로 정답으로 채택해서는 안 된다.

하지만 쟁점 검증 결과에는 `ISSUE_LEASE_TERMINATION` 한 건만 남았다. 갱신에 따른 현재 계약 상태와 향후 종료 절차가 별도 쟁점으로 다뤄지지 않는다. 최종 조립은 이 한 건의 정형 권고와 일반 확인 목록을 사용한다.

실제 최종 핵심 결론은 ‘기초 권리관계를 확인 중이며 현재 권리관계와 종료 여부를 추가 확인해야 한다’는 수준이다. 핵심 사실에는 잔금액, 계약금, 이체 확인번호가 선택되고, 이번 질문의 중심인 E04의 만기 후 계속 거주·별도 계약서 미작성·갱신거절 미수령 진술은 본문 핵심 설명에서 빠졌다.

따라서 종료의 확정 단정을 막는 것과 별개로 **현재 계약 상태와 앞으로의 종료 방법에 답하지 못했다.** 불확실성을 표시하면서도 확보한 법령에 근거한 조건부 설명을 제공하는 경로가 필요하다.

## 4. 당사자 진술이 최종 답변에서 확인된 사실처럼 표시되었다

이 trace의 전입신고일 사실 한 건은 다음과 같이 저장되어 있다.

- Fact ID: `95f348ca-8534-454e-8419-3d8bcddb3c8d`
- 출처: E03.
- `adjudication_status = PARTY_ALLEGED`
- `trust_level = EVIDENCE_SUPPORTED`

최종 답변은 이 전입신고일을 일반 ‘판단 근거’ 항목으로 출력하고 진술·미확인 표식을 붙이지 않았다.

`select_grounded_facts_for_display()`가 adjudication 상태와 trust_level을 OR 조건으로 결합하여 당사자 진술 상태를 우회한다. 기존 `is_fact_strictly_verified()`의 보수적 기준과 표시 단계가 일치하지 않는다. 등록 문서에 기재되어 있다는 사실과 그 문서 내용이 독립 증거로 입증되었다는 판단을 분리해야 한다.

## 6. 다음 수정에서 반드시 검증할 기준

1. 검증 프롬프트를 출처 추가 순서의 앞 6개로 자르지 말라. 인용·쟁점별 필수 법령과 증거를 선택하고, 전체 레지스트리·실제 전달 목록·생략 목록을 구분하여 관측하라. 전달하지 않은 문서를 검색되지 않았다고 판정하게 만들지 말라.
2. E01~E03 기초 분석과 E04 추가 후 갱신·종료 질문을 별도 회귀 사례로 고정하라. ‘현재 상태’와 ‘앞으로 할 일’에 각각 답하는지 검사하라.
3. 당사자 진술은 문서 승인 여부나 trust_level만으로 확정 사실에 승격하지 말라. 추출·심리·표시 단계의 상태 우선순위를 통일하라.
4. 일반 조문 설명과 사건 적용을 구분하라. 진술이 사실일 경우의 조건부 법률 설명은 허용하되, 통지 원문·도달일·지정 종료일을 확인하지 않고 구체적 종료일을 확정하지 말라.
5. 최종 답변의 문장·쟁점별 근거와 사용자 질문 커버리지를 검증하라. 원래 초안에 대한 검사만으로 최종 정형 조립 결과의 정확성과 유용성이 보장된다고 보지 말라.
6. 완료 기준에 실제 Langfuse 요청의 검색→검증 입력→최종 답변 대조를 포함하라. 합성 브리핑과 가짜 LLM 기반 테스트 통과를 실제 서비스 검증 완료로 보고하지 말라.

이전 수정 보고서의 ‘실제 Azure·DB·브라우저 E2E 미검증’ 항목은 이번에도 중요하다. 이번에는 실제 기존 trace에서 그 공백이 드러났으며, 수정 결과를 실제 서비스 품질의 완료 판정으로 확대할 수 없음을 확인했다.
