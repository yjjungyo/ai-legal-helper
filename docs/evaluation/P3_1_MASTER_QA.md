# P3.1 Legal Action Intelligence AI Master QA

**Q. 왜 단순 법률 상담을 넘어 Action Planner를 개발했는가?**
단순 텍스트 생성은 사용자에게 "어떻게 해야 하는지"를 명확하게 지시하지 못해 실질적 문제 해결을 돕지 못합니다. 구조화된 Action Plan은 사용자가 단계별로 실행하고 상태를 추적할 수 있도록 돕습니다.

**Q. 왜 LLM에게 모든 행동 결정을 맡기지 않았는가?**
법률적 대응은 절차와 요건, 기한이 엄격하게 정해져 있습니다. LLM이 자유롭게 행동을 지어낼 경우 실무와 무관한 위험한 행동을 권고할 우려가 있습니다. 따라서 "Action Catalog"라는 Rule 기반 후보군 안에서만 선택하도록 제한(Hybrid 방식)했습니다.

**Q. 행동 추천의 법률적 신뢰성을 어떻게 확보했는가?**
추천된 각 행동마다 필요한 선행 조건(`Requirement`)을 명시하게 하고, 이것이 기존 사건의 팩트와 증거 기반인지 확인하여 `satisfaction_status`를 판단하게 했습니다. 명확한 근거(증거)가 없다면 UNSATISFIED 상태로 제시하여 위험을 알립니다.

**Q. 법률상 기한을 어떻게 계산하고 검증하는가?**
결정론적 로직(`DeadlineEngine`)을 도입했습니다. 이벤트(타임라인)에서 계약 종료일을 추출하고, 주택임대차보호법 기준에 따라 파이썬 `datetime` 연산을 통해 정확히 2개월 전 등의 기한을 산출합니다. LLM 연산을 배제했습니다.

**Q. 사건 변경 시 대응 계획을 어떻게 유지하는가?**
사용자가 새로운 진술을 추가하거나 증거가 승인/반려되면 `CaseRevision` 버전을 올립니다. 이때 사용자가 "재평가" 버튼을 누르거나 API를 호출하면, 새 컨텍스트를 기반으로 다시 `LegalAction`을 도출하고 기존 Plan 버전을 올립니다(ActionRevision).

**Q. GraphRAG는 행동 추천에 어떤 실질적 기여를 하는가?**
Neo4j 기반의 Graph 검색 결과를 Action Planner에게 Context로 제공하여, 단편적인 의미 기반 검색으로는 연결되지 않았던 간접적 증거와 사실관계를 종합해 `ActionRequirement` 판단을 돕습니다.

**Q. 이 기능이 사용자에게 제공하는 비즈니스 가치는 무엇인가?**
법률 비전문가인 사용자가 막연한 불안감에서 벗어나 "지금 당장 해야 할 일"과 "준비해야 할 증거"를 명확한 체크리스트 형태로 파악할 수 있게 하여, 법적 대처 비용과 시간을 크게 줄여줍니다.
