# Azure OpenAI: GPT-5.4 → GPT-6.1 Sol 변경 검토

- 검토일: 2026-10-17
- 대상: 법률 서비스의 Azure OpenAI 채팅 모델
- 전제: 현재 GPT-5.4 사용은 사용자 설명 기준이다. Azure 관리 화면의 실제 배포 모델·버전은 조회하지 않았다.
- 수행 범위: 공식 OpenAI 문서와 현재 코드의 읽기 전용 검토. 배포·설정 변경, 유료 모델 호출, 실제 A/B 평가는 수행하지 않았다.

## 1. 결론

`gpt-6.1-sol`은 비교 평가할 가치가 있다. 다만 현 시점에서는 서비스 전체의 즉시 교체보다 검색·검증 오류 수정 후 검증 노드와 법률 답변 노드부터 제한적으로 비교하는 방식을 권고한다.

이번 문제에는 출처 전달 누락, 적용 특별법 원문 부족, 검증 실패 처리, 오류 초안 재노출이 함께 관여한다. 모델의 추론 능력이 좋아져도 비어 있는 출처 목록이나 잘못된 종료 정책을 자동으로 해결하지는 못한다. 이 서비스의 한국 법률 정확도가 GPT-5.4보다 높아진다는 실측 근거는 아직 없다.

## 2. 공식 문서로 확인한 차이

| 항목 | GPT-5.4 | GPT-6.1 Sol |
|---|---|---|
| 추론 노력 | none 기본, low/medium/high/xhigh | medium 기본, low/medium/high/xhigh/max; none 미지원 |
| 컨텍스트 / 최대 출력 | 1,050,000 / 128,000 | 1,050,000 / 128,000 |
| 도구 호출 | 기존 구현과 별도 호환 확인 | 공식 OpenAI 문서상 Responses API 필요 |
| 한국 법률 서비스 정확도 | 이번 비교 실측 없음 | 이번 비교 실측 없음 |

출처: [GPT-5.4](https://developers.openai.com/api/docs/models/gpt-5.4), [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol).

위 사양은 OpenAI API 문서 기준이다. Azure의 해당 리소스·지역·배포 유형에서 동일한 모델과 기능을 사용할 수 있는지는 별도 확인 대상이다. OpenAI 모델 ID가 확인되었다고 Azure 배포명으로 그대로 사용할 수 있다고 단정하지 않는다. Azure 미지원이라고 판정한 것도 아니다.

## 3. 현재 코드와 충돌할 수 있는 지점

### 3.1 배포명만 바꾸는 전환은 부적절

`backend/src/ai_legal_helper/llm/gateway.py`는 `AzureChatOpenAI`에 배포명과 `temperature=0.0`을 전달한다. Responses 사용과 추론 노력 설정은 명시되어 있지 않다. API 버전은 환경변수를 사용하고 코드 기본값은 `2024-02-15-preview`다. 실제 적용 API 버전은 이 검토에서 확인하지 않았다.

현재 아래 호출은 `with_structured_output(..., method="function_calling")`을 사용한다.

- `agents/action_planner.py`
- `case_intelligence/evidence_extractor.py`
- `workflows/document_workflow.py`

공식 OpenAI 문서는 GPT-6.1 Sol의 도구 호출에 Responses API를 요구하며 Chat Completions는 도구 없는 요청을 지원한다고 설명한다. 따라서 현재 구조화 출력 경로는 전환 전 필수 호환성 검사 대상이다. 모든 구조화 출력이 불가능하다는 의미는 아니다. Azure와 SDK가 지원하는 경로를 확인해야 한다. [모델 문서](https://developers.openai.com/api/docs/models/gpt-6.1-sol)

### 3.2 temperature와 SDK 처리

공식 GPT-6 가이드는 reasoning effort가 none이 아닐 때 `temperature`, `top_p`, `top_logprobs`를 제거하도록 안내한다. GPT-6.1 Sol은 none을 지원하지 않으므로 현재의 temperature 전달을 그대로 유지하는 전환은 피해야 한다. [GPT-6 API 호환성](https://developers.openai.com/api/docs/guides/latest-model)

설치된 LangChain 코드에는 Responses 지원 분기가 있지만, 확인한 temperature 자동 조정 로직은 `gpt-5` 이름을 대상으로 한다. 라이브러리가 GPT-6.1 Sol 설정을 알아서 보정하리라 가정하지 말라. Azure 배포명과 실제 모델명이 다를 때의 처리도 확인해야 한다.

### 3.3 전환 영향 범위

여러 노드가 공통 `get_llm()`을 사용하므로 기본 배포명을 바꾸면 라우팅·질의 재작성·전문가·종합·검증뿐 아니라 증거 추출·액션 계획·문서 작성에도 영향이 생길 수 있다. 검증 노드만 비교하려면 역할별 선택 기능이 필요하다. 현재 이미 역할별 전환이 구현되었다고 보지 않는다.

채팅 모델과 임베딩 배포는 별도로 생성된다. 임베딩 모델과 인덱스 설정을 유지하면 채팅 모델 변경만을 이유로 전체 재임베딩할 필요는 없다. 다만 검색 질의가 바뀌면 검색 결과는 달라질 수 있다.

## 4. 비용·지연 판단

참고로 OpenAI 직접 API의 일반 텍스트 표준 단가는 다음과 같다. 입력 272K 이하, 캐시·Batch·Fast·지역 가산 등을 제외한 비교다.

| 100만 토큰당 USD | GPT-5.4 | GPT-6.1 Sol |
|---|---:|---:|
| 입력 | 2.50 | 2.00 |
| 출력 | 15.00 | 10.00 |

출처: [GPT-5.4 가격](https://developers.openai.com/api/docs/models/gpt-5.4), [GPT-6.1 Sol 가격](https://developers.openai.com/api/docs/models/gpt-6.1-sol).

이 표는 Azure 견적이 아니다. Azure 계약·지역·배포 유형별 단가를 확보하기 전에는 실제 비용 절감을 확정할 수 없다. 추론 토큰과 호출 횟수가 달라질 수 있으므로 요청 1건당 총비용과 p50/p95 지연으로 비교해야 한다. 최신 모델이라는 이유로 더 빠르다고 판단하지 않는다.

## 5. 권장 평가 순서

1. 먼저 RAG 수정 지시문의 출처 전달, 보수적인 검증, 오류 결론 차단을 완료한다. 이때 기본 모델은 유지한다.
2. Azure 포털·관리 API에서 실제 모델 ID·버전, 지역, 배포 유형, 할당량, 가격, Responses·도구·구조화 출력 지원과 데이터 처리 조건을 확인한다.
3. 별도 후보 배포에서 일반 응답, 도구 호출, 현재 3개 구조화 출력 스키마, 스트리밍, 토큰·비용 추적, 오류 처리를 시험한다.
4. 개인정보를 제거한 고정 평가 세트와 동일한 법령 스냅샷으로 검증 노드부터 비교한다. 시작 후보는 GPT-6.1 Sol medium으로 하고 어려운 사례만 high를 추가 비교한다. 이는 실험 제안이며 성능 보장은 아니다.
5. 고정 초안·고정 출처로 검증 성능을 비교한 뒤, 검색부터 최종 답변까지 전체 성능을 별도로 비교한다. GPT-5.4도 현재 설정과 medium 설정을 구분하여 모델 효과와 추론 노력 효과를 분리한다.
6. 통과한 경우 전문가·종합 노드로 확대하고 마지막에 전체 전환을 판단한다. 기존 배포로 되돌릴 수 있게 유지한다.

평가 사례에는 특별법 누락, 일반법 오적용, 기간·기산점 오류, 실제 출처가 있지만 주장을 지지하지 않는 경우, 검증 API 실패, 근거 없는 질문, 정상 PASS 사례를 모두 포함한다. 법률 검토자가 정답과 적용 조건을 확인해야 하며 LLM 단독 채점을 최종 판정으로 삼지 않는다.

승인 기준은 시험 전에 정한다. 이 문제의 필수 회귀 세트에서는 검증 실패 후 확정적 오류 답변 노출 0건을 요구한다. 전체 평가에서는 오류 답변의 PASS 비율, 정답의 불필요한 거절 비율, 적용 법령·기간·기산점 정확도, 출처 추적 가능성, 구조화 출력 실패율, 요청당 비용과 지연을 함께 비교한다. 회귀 세트 통과가 운영 전체의 무오류를 보장하지는 않는다.

## 6. 현재 판단의 한계와 전달 사항

- Azure 실제 제공·리소스 접근·가격·할당량: 미확인.
- 실제 모델 호출과 한국 법률 A/B 평가: 미실행.
- 모델 변경 또는 설정 수정: 수행하지 않음.
- 권고: 조건부 평가 진행. 구조적 오류 수정과 모델 전환을 별도 변경으로 관리.

ChatGPT 또는 구현 담당자에게는 이 문서와 [RAG 수정 지시문](../instructions/RAG_VERIFICATION_RECOVERY_FIX_INSTRUCTION_v1.0.md)을 함께 전달하라. 검토 문서 작성과 실제 구현·전환 완료를 구분하여 보고해야 한다.
