## 2. End-to-End Sequence Diagram

```mermaid
sequenceDiagram
    autonumber
    participant User as User
    participant React as React (EvidenceSection.tsx)
    participant FastAPI as FastAPI (routes/evidence.py)
    participant Service as evidence_ingestion.py
    participant FS as Local File System (./storage/evidence)
    participant PostgreSQL as PostgreSQL (:5432)
    participant Langfuse as Langfuse (:3001)

    User->>React: '+ 증거 파일 업로드' 클릭 -> .pdf/.docx/.txt 파일 선택
    React->>React: handleUpload(e) -> uploading = true, FormData 생성
    React->>FastAPI: POST /api/v1/cases/{case_id}/evidence (FormData: file)
    FastAPI->>Langfuse: create_trace(name="api_request", case_id=case_id)
    FastAPI->>FastAPI: Depends(verify_case_ownership)
    FastAPI->>Service: ingest_evidence(db, case_id, file, document_type)
    Service->>Service: 확장자(.pdf/.docx/.txt) 및 MIME 타입 검증
    alt 허용되지 않는 확장자 또는 MIME 불일치
        Service-->>FastAPI: HTTPException(400, "지원하지 않는 파일 확장자/MIME")
        FastAPI-->>React: HTTP 400 Bad Request
    else 검증 통과
        Service->>Service: await file.read() -> SHA-256 file_hash 계산
        Service->>PostgreSQL: SELECT * FROM evidence_documents WHERE case_id=:cid AND file_hash=:hash
        alt 동일 파일 해시 존재 (중복 업로드)
            Service-->>FastAPI: HTTPException(409, "이미 업로드된 동일한 증거 파일이 존재합니다")
            FastAPI-->>React: HTTP 409 Conflict
        else 신규 파일
            Service->>FS: ./storage/evidence/{uuid4()}.{ext} 파일 저장
            Service->>PostgreSQL: INSERT INTO evidence_documents (status='UPLOADED', file_hash, storage_path, ...)
            alt DB Commit 실패
                PostgreSQL-->>Service: Exception -> db.rollback()
                Service->>FS: os.remove(storage_path) (고아 파일 롤백 삭제)
                Service-->>FastAPI: HTTPException(500)
            else DB Commit 성공
                PostgreSQL-->>Service: doc refresh 완료
                Service-->>FastAPI: EvidenceDocument 반환
                FastAPI->>FastAPI: background_tasks.add_task(run_extraction_pipeline, doc.id) (EVT-009 자동 예약)
                FastAPI-->>React: HTTP 200 OK EvidenceDocumentResponse
                React->>React: await loadEvidences(), await loadConflicts(), setSelectedDocId(newDoc.id)
                React-->>User: 좌측 증거 목록에 신규 문서 표시 및 자동 선택
            end
        end
    end
```

## 3. 13단계 실행 경로 상세 추적

1. **이벤트 발생 화면 및 컴포넌트**: 워크스페이스 `evidence` 탭의 [`EvidenceSection.tsx`](file:///c:/myprjs/ai-legal-helper/frontend/src/components/EvidenceSection.tsx) 상단 `+ 증거 파일 업로드` 버튼 및 숨겨진 `<input type="file" accept=".pdf,.docx,.txt">`.
2. **이벤트 핸들러**: `handleUpload`(`EvidenceSection.tsx:311-334`) → `uploadEvidence(caseId, file)`([`api/evidenceClient.ts:52-63`](file:///c:/myprjs/ai-legal-helper/frontend/src/api/evidenceClient.ts#L52-L63)).
3. **호출되는 API와 HTTP Method**: `POST /api/v1/cases/{case_id}/evidence` (`multipart/form-data`).
4. **FastAPI Router**: [`api/routes/evidence.py:50`](file:///c:/myprjs/ai-legal-helper/backend/src/ai_legal_helper/api/routes/evidence.py#L50) `upload_evidence()`.
5. **Service / Repository 함수**: [`case_intelligence/evidence_ingestion.py:67`](file:///c:/myprjs/ai-legal-helper/backend/src/ai_legal_helper/case_intelligence/evidence_ingestion.py#L67) `ingest_evidence()`.
6. **DB 읽기·쓰기**:
   - PostgreSQL `evidence_documents`에서 `(case_id, file_hash)` 중복 여부 `SELECT`.
   - Local FS `./storage/evidence/{uuid}{ext}`에 바이너리 기록.
   - PostgreSQL `evidence_documents`에 `status="UPLOADED"`로 `INSERT`.
7. **AI Agent 또는 RAG 호출**: 업로드 요청 자체에서는 동기 호출하지 않으나, 반환 직전 `background_tasks.add_task(run_extraction_pipeline, doc.id)`를 통해 [`EVT-009`](EVT-009.md)를 백그라운드에서 즉시 실행한다.
8. **외부 LLM·도구 호출**: 없음 (`EVT-009`에서 수행).
9. **응답 JSON 구조** (`EvidenceDocumentResponse` — [`api/schemas/evidence.py:13-29`](file:///c:/myprjs/ai-legal-helper/backend/src/ai_legal_helper/api/schemas/evidence.py#L13-L29)):
