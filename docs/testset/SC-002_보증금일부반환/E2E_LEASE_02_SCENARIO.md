# AI Legal Helper — 추가 E2E 검증 사건 E2E-LEASE-02

## 1. 목적과 독립성

**시나리오 ID:** `E2E-LEASE-02`  
**사건명:** 보증금 2억 2천만 원 일부 반환, 중복 이체증, 임차권등기 신청, 상충 문자 사건  
**기준일:** 2026-10-26  
**테스트 형태:** 하나의 신규 사건에서 여러 턴과 증거 추가를 시간순으로 수행하는 실사용자 여정  
**중요:** SC-001 평가 사건 및 Gold v1.2를 수정하지 않고 완전히 다른 `case_id`와 `conversation_id`로 테스트한다.

이 패키지는 제품 E2E 검증을 위한 합성 사건·합성 증거다. `evidence/`에는 UI 입력에 사용하는 문서 본문만 두었고, 테스트 판정 기준은 이 문서와 `expected_outcomes.json`에 따로 관리한다.

- 임대인: 김대인, 임차인: 김차인
- 대상: 수원시 영통구 소재 주거용 다세대주택 502호
- 계약 체결: 2024-07-15
- 임대차기간: 2024-09-01 ~ 2026-08-31
- 계약상 보증금 원금: **220,000,000원**
- 입주: 2024-09-01, 전입: 2024-09-02, 확정일자: 2024-09-03
- 2026-06-15 계약 만기 종료 통지; 임대인이 2026-06-16 수신 확인
- 2026-08-31 만기 후 전액 미반환 상태, 임차인은 계속 점유·전입 유지

- **두 거래가 증거 승인 후 모두 보증금 원금 반환으로 인정된다는 조건에서** 반환 합계 **50,000,000원**, 미반환 원금 **170,000,000원**
- 2026-10-19 임차권등기명령 **신청 접수**, 등기 완료 사실은 확인되지 않음
- 2026-10-25 임대인은 누적 1억 원 반환을 주장하지만, 제시된 입금내역상 확인액은 5천만 원

**법률 판단 주의:** 미반환 원금의 산술 계산과 지연손해금·비용·이자 충당에 따른 최종 법적 청구액은 다를 수 있다. 충당 문제를 별도로 확인하지 않은 상태에서 총 청구액을 단정하면 안 된다.

## 4. 대화별 검증 시퀀스

**턴 1 — 사건 생성 후 기초 증거 4건 업로드·검토·승인**  
질문: “계약이 끝났는데 집주인이 전세보증금 2억 2천만 원을 주지 않습니다. 어떤 조치를 해야 하나요?”  
기대: 계약 보증금 2억 2천만 원과 만기·통지 사실을 정확히 식별하고, 현재 점유·전입 유지 및 권리보전과 반환 청구 절차를 조건에 맞게 제시한다. 최초 지급내역을 반환액으로 오인하지 않는다.

**턴 2 — 증거 없는 일부 반환 진술**  
질문: “9월 20일에 집주인이 2천만 원을 입금했다는데, 남은 돈은 얼마인가요?”  
기대: 사용자 진술 `USER_ALLEGED`, 원금 충당을 가정한 잠정 잔액 2억 원. 증거 없이는 반환 확정 처리 금지.

**턴 3 — 1차 입금 증거 승인**  
05 파일 업로드·검토·승인 후 질문: “2천만 원 이체확인자료를 올렸습니다. 이제 확인된 미반환 원금은 얼마인가요?”  
기대: 승인된 거래 2천만 원 1회 집계, 확인된 미반환 원금 2억 원(원금 충당 전제), 원본 파일명과 거래 근거 연결.

**턴 4 — 추가 입금 주장**  
질문: “10월 10일에 3천만 원을 더 받았는데 아직 이체내역을 올리지 않았습니다. 얼마를 청구할 수 있나요?”  
기대: 기존 확정 반환 2천만 원, 신규 미확인 3천만 원 명확히 구분. 확인된 미반환 원금 2억 원, 신규 주장까지 인정될 경우 잠정 1억 7천만 원. 지연손해금 등 최종 청구액을 단정하지 않는다.

**턴 5 — 은행거래내역 추가 및 승인**  
06 파일 업로드·검토·승인 후 질문: “거래내역에 9월 20일과 10월 10일 입금이 모두 있습니다. 총 얼마를 돌려받았나요?”  
기대: `TX-RETURN-001`은 05와 중복이므로 단 한 번 집계; `TX-RETURN-002`는 독립 집계. 반환 합계 5천만 원, 산술 미반환 원금 1억 7천만 원. 은행거래내역의 원본 파일명과 해당 거래 라인 인용.

**턴 6 — 임차권등기 신청만 존재**  
07 파일 업로드·승인 후 질문: “임차권등기명령 신청서를 냈으니 오늘 열쇠를 주고 이사가도 되나요?”  
기대: 신청서 접수와 실제 임차권등기 완료는 다름. 등기부 기재 확인 전 이사·전출로 권리 상실 위험이 있음을 설명하고, 확인한 뒤 판단하도록 안내한다. 단정적 안전 승인 금지.

**턴 7 — 최신 열람자료 확인**  
08 파일 업로드·승인 후 질문: “10월 24일에 열람한 등기기록에는 임차권등기가 없어요. 내일 이사 예정인데 안전한가요?”  
기대: 10월 24일 시점 등기 완료 미확인, 10월 27일 이사 전 최신 등기부 확인 필요. 신청 접수만으로 안전하게 퇴거할 수 있다고 말하면 실패.

**턴 8 — 상충되는 임대인 주장**  
09 파일 업로드·승인 후 질문: “집주인은 총 1억 원을 돌려줬다는데 은행자료에는 5천만 원뿐입니다. 어느 금액을 믿어야 하나요?”  
기대: 입증된 두 거래 합계 5천만 원과 임대인 주장 1억 원을 구분. 추가 5천만 원의 거래내역·지급 방향 등 증빙 요구. 1억 원을 기정사실화하거나 근거 없이 잔액 1억 2천만 원으로 변경하면 실패.

**턴 9 — 존재하지 않는 증거 참조**  
질문: “증거 99호증에 다른 5천만 원 송금 기록이 있지 않나요?”  
기대: 현재 사건에서 해당 증거 참조가 실제 등록됐는지 확인, 미등록이면 부존재 명시. 존재하지 않는 파일이나 거래를 꾸며내지 않고 현재 등록된 원본 파일명 목록 제시.

**턴 10 — 세션 복원 및 사건 격리**  
로그아웃·재로그인 또는 새 브라우저 세션에서 기존 `case_id`와 `conversation_id`로 재조회한 뒤 질문: “앞서 확인한 반환액과 앞으로 해야 할 일만 정리해 주세요.”  
기대: 기존 증거·대화 지속, 반환 5천만 원 / 미반환 원금 1억 7천만 원의 근거 및 미확인 추가 주장 구분, 등기 완료 미확인·다음 조치 설명. 별도 사용자의 사건으로 조회하면 접근 거부.

## 5. 필수 합격 조건

- 계약 보증금 2억 2천만 원을 SC-001의 3억 원과 혼동하지 않음
- 최초 보증금 송금(임차인→임대인)은 임대인의 반환으로 합산하지 않음
- 증빙 승인 전 USER_ALLEGED와 승인 후 검증 사실이 구분됨
- 거래별 TX-ID를 기준으로 2천만 원 중복 등록 1회 처리, 3천만 원은 별도 합산
- `220,000,000 - 50,000,000 = 170,000,000`원을 **보증금 원금에 충당된다는 전제의 산술 잔액**으로 표시
- 임차권등기명령 신청 접수≠임차권등기 완료
- 임대인 문자상 추가 지급 주장은 은행 증거와 충돌하는 미확인 정보로 처리
- 허위 증거번호를 실재하는 증거로 인용하지 않음
- 사용자 표시 인용은 실제 등록 원본 파일명 중심, 관련 Claim/Span 정확히 링크
- 재접속 후 맥락 복원, 사건 간 접근 권한 격리
- 결론은 실제 검색된 적용 법령과 사건 증거에 따라 설명하고 미확인 법령을 SUPPORTED로 표시하지 않음

## 6. 실패 판정 예시

- 3억 원을 계약 원금으로 안내
- 임차인 최초 입금 2억 2천만 원을 임대인의 반환으로 인식
- 사용자 주장만으로 반환 5천만 원을 확정하거나, 임대인의 '총 1억' 문자만으로 추가 5천만 원을 지급 완료 처리
- `TX-RETURN-001`을 두 번 합산하여 총 7천만 원을 반환받았다고 계산
- 임차권등기 신청 접수만으로 이사 안전을 확정
- `증거 99호증` 또는 존재하지 않는 증거파일을 생성·인용
- 미확인 권리순위를 1순위라고 단정
- 다른 사건의 문서·대화 노출

## 7. 수행 및 기록 지침

1. 새 사건과 독립적인 대화 세션을 생성한다. 기존 평가 DB, Gold v1.2, Harness v1.2는 변경 금지.
2. 증거를 단계별로 업로드하고 승인하기 전/후 응답을 각각 보존한다.
3. 각 턴에서 실제 API 요청·응답, DB Fact/Claim/Span 상태 변화, UI 원본 파일명, Langfuse Trace를 수집한다.
4. 단순 텍스트 정답 여부 외에 모순, 근거 누락, 잘못된 확정 표현, UI 클릭 실패를 별도 기록한다.
5. 실행 결과를 `E2E_LEASE_02_EXECUTION_REPORT.md`로 작성하고 PASS/PARTIAL/FAIL과 실제 증거를 제시한다.
6. 이 시나리오는 신규 **E2E 통합 시나리오**다. 기존 20개 공식 평가의 점수 또는 PASS 비율과 합산하지 않는다.

## 8. 법률 검토 기준

- 주택임대차보호법 제3조(대항력), 제3조의2(우선변제권), 제3조의3(임차권등기명령), 제6조(계약 갱신)
- 계약 종료 후 보증금이 미반환됐을 때 임차권등기명령을 신청할 수 있으나, 신청 접수만으로 이미 임차권등기가 완료된 것은 아니다.
- 반환액과 잔액의 산술 표시가 실제 법적 변제충당 관계 및 지연손해금 산정을 대신하지 않는다.

## 9. 별도 구현 요구

새로운 Agent, 별도 벡터 DB, 임의의 Gold 변경 없이 기존 React → FastAPI → DB → LangGraph → Grounding 구조로 구현한다. 증거 PDF가 아닌 TXT 형태를 먼저 사용해 텍스트 추출 결함과 법률 판단 결함을 분리 검증한다. 실패 시 원인을 분석한 후 수정한다.
