# 문서 원문 기반 상담 경로 변경 및 실제 검증 보고서

## 현재 판정

코드의 답변 경로를 변경하고 실제 모델 재현을 완료했다. **기초 자료 분석은 검증 통과 후 조건부 답변으로 전달되었으나 갱신 질문은 최종 보류되었다. 전체 답변 품질 문제 해결 또는 POC 기준선 확정으로 보고할 수 없다.** 브라우저 전체 E2E와 배포는 이번 재현 범위에 포함하지 않는다.

## 변경 이유

기준 실패 trace는 `fd714ae8-a876-4b3b-b402-3e3ce6e825dd`다. 법령 검색으로 확보한 44개 출처 중 공식 법령 20개가 뒤에 추가되었으나 검증 LLM은 앞 6개 출처의 400자씩만 읽었다. 또한 갱신 상태와 종료 방법을 설명한 초안이 최종 조립기의 일반적인 사건 안내로 덮어써졌다.

이전의 키워드·쟁점별 정형 문구 수정만으로는 질문 의도와 원문에 맞는 답변을 확보하지 못했다. 새 경로는 현재 질문과 등록 문서 원문으로 직접 작성하고 그 답변 자체를 검증한다.

## 변경된 실행 경로

등록 문서가 있는 사건:

`현재 질문 → 사건 문서 원문 → 법률 자료 검색 → 한 작성자의 답변 → 질문·사실·법률·일관성 검증 → 필요 법령 승인 검색 또는 재작성 → 검증한 동일 답변 출력`

- 문서 원문은 현재 사건에 속한 `EvidenceDocument`와 `EvidenceSpan`에서 읽는다. 원본 파일이나 다른 사건 문서의 임의 경로를 읽지 않는다.
- 승인되지 않은 문서는 목록과 상태만 전달하고 본문은 근거로 전달하지 않는다.
- 파생 Fact 요약과 이전 AI 답변을 새 작성자의 사실 근거로 사용하지 않는다. 지시어 이해에 필요한 이전 사용자 발언은 미입증 진술로 전달한다.
- 분야 분류는 법률 검색에 사용한다. 문서 질문을 일률적인 후속 행동 안내나 사건 변동 비교로 바꾸지 않는다.
- 문서 사건에서는 전문 에이전트별 답변을 여러 개 생성하지 않는다. 법률 검색 후 한 작성자가 답변한다.
- 등록 문서가 없는 기존 일반 상담 경로는 유지한다. 순수 인사·감사는 법률 검증 대상에 넣지 않는다.

## 작성·검증의 공통 근거

`rag/grounding_context.py`가 실제 출처 전체를 같은 형식으로 전달한다. 앞의 몇 개 또는 본문의 앞 몇 자만 조용히 전달하는 제한을 제거했다.

- 출처 ID·개수·본문 해시·누락 여부를 기록한다.
- 작성과 검증의 출처 해시가 다르면 검증을 완료하지 않는다.
- 원문 예산 120,000자 초과 또는 동일 출처 ID의 서로 다른 본문은 명시적 실패로 처리한다. 대량 문서의 자동 요약·선별 기능을 구현했다고 주장하지 않는다.
- 사건 문서의 인용 ID는 현재 사건의 `E01` 등 짧은 라벨을 사용하고 실제 UUID는 `evidence_id`에 보존한다.
- 작성·검증·최종 출력 사이에 문서가 삭제·반려·재추출·변경되었는지 사건 소유, 파일명, 해시, 추출 버전 및 추출 시점으로 확인한다.

## 검증과 최종 출력

문서 상담에는 일반 법령 질의용 정책과 분리한 `document_verification_prompt.py`를 적용한다.

1. 현재 질문의 각 요청에 실제로 답했는지 확인한다.
2. 첫 결론, 시간 순서, 의사표시 내용, 증명 수준의 일관성을 검사한다.
3. 검증할 주장은 실제 답변 문구 그대로 인용하도록 한다. 단정을 조건부 문장으로 바꾸어 검증하지 않는다.
4. 계약 약정의 소개·지급 내역 대조 같은 사실 평가와 법률 규칙의 적용을 구분한다.
5. 미입증 전제를 명시한 조건부 법률 설명은 전제의 실제 입증 여부와 구분하여 평가한다.
6. 존재하지 않는 출처, 문서만으로 지지한 법률 규칙, 근거 없는 핵심 사실·법률 주장이 남으면 통과시키지 않는다.

필요한 법령이 없으면 기존 승인 검색으로 연결한다. 같은 법의 일부 조문이 있다는 이유로 다른 누락 조문까지 확보했다고 보지 않는다. 공식 검색 후 재분석을 포함한 재작성은 총 두 번 이내로 제한한다. 통과하지 못한 답변은 성공한 조언으로 출력하지 않는다.

최종 단계는 검증한 초안을 다시 조립하지 않는다. 검증 당시 답변 해시와 현재 초안이 같은지 확인한 후 그대로 출력한다. `CAUTIONARY`는 미확인 사건 전제가 있는 검증된 조건부 설명을 의미하며, 미통과 초안을 통과로 바꾸는 용도로 사용하지 않는다.

## 실제 재현에서 확인한 문제와 처리

- 최초 재현 중 검증기가 PASS를 반환했지만 첫 결론과 후속 통지의 효과가 맞지 않는 답변이 발견되었다. 해당 결과는 수동 불합격으로 표시하고 POC 통과 근거에서 제외했다.
- 지급 사실 평가나 계약서 약정 소개를 법률 규칙으로 오분류하여 불필요하게 재작성을 요구하는 경우가 있었다. 분류 기준을 명확히 했다.
- 긴 증거 UUID를 검증 응답이 오기재하는 경우가 있어 현재 사건의 짧은 라벨을 인용 ID로 사용했다.
- 검증 함수 반환 객체에 후속 필드를 추가하면서 Langfuse 비동기 직렬화에 `dictionary changed size during iteration` 오류가 발생했다. 추적 중인 반환 객체를 변경하지 않고 새 객체를 생성하도록 수정했다.
- 앞 단계가 끝난 뒤의 노드명으로 부모 Span을 찾다가 루트에 연결되는 `SPAN_PARENT_UNRESOLVED` 경고는 기존 추적 계층의 잔여 한계다. 모든 관측성 문제가 해결되었다고 보고하지 않는다.

## 법제처 검사 두 건의 실패 원인 재확인

처음에는 제한된 실행 환경에서 `WinError 10013`으로 법제처 서버 접속이 차단되어 빈 결과를 받았다. 이는 성공한 API 응답의 내용이 틀린 것과 다르다.

외부 접속이 가능한 실행으로 다음 두 검사를 그대로 재실행했고 **2 passed**를 확인했다.

- `test_search_official_statutes_civil_act_exact_match`: 민법 검색이 난민법 등으로 섞이지 않는지 확인.
- `test_search_official_statutes_dynamic_missing_issues_boost`: 누락 쟁점을 반영하여 관련 조문이 수집되는지 확인.

이 결과는 해당 두 요청의 실제 API 동작 확인이며 모든 법령 검색의 품질 보증은 아니다.

## 검증 기록

- 중간 확장 단위 검사: 454 passed, 2 failed, 5 deselected. 실패 두 건은 위 법제처 검사이며 외부 접속 재실행에서 통과했다. 제외한 5건을 통과로 집계하지 않는다.
- 변경 경로 및 기존 상담 회귀 검사 7개 파일: **106 passed**. 이 중 새 문서 상담 검사 21건에는 실제 LangGraph 연결, 문서 범위, 원문 전달, 문구 변조, 질문 누락, 일관성 검사 누락, 문서 변경, 추적 반환 객체 변경 방지 반례가 포함된다. LLM을 대체한 검사이므로 실제 답변 품질 통과와 구분한다.
- 프런트엔드 실제 인용 렌더러 검사: 2 passed.
- `git diff --check`: 오류 없음. 저장소의 LF/CRLF 변환 경고는 별도로 존재한다.
- 실제 모델 배포는 기존 `gpt-5.4`를 사용했다. 모델이나 의존성을 새로 도입하지 않았다.

실제 재현 스크립트는 `backend/scripts/replay_document_consultation.py`다. 사건 DB는 조회만 하고 기존 trace에서 승인 검색된 공식 법령 20개를 재사용한다. E01~E03 기초 분석과 E01~E04 갱신 질문을 구분한다. 이는 신규 법령 검색·승인 UI·상담 저장·브라우저 화면까지의 전체 E2E가 아니다.

최신 결과 문서:

- `docs/evaluation/SC001_DOCUMENT_CONSULTATION_OVERVIEW_RESULT_2026-10-30.md`
- `docs/evaluation/SC001_DOCUMENT_CONSULTATION_RENEWAL_RESULT_2026-10-30.md`

각 재현 문서에 실제 사용자 답변, 검증 실행 내역, 출처 명세, trace ID 및 실행 시점 소스의 SHA-256을 기록한다. 과거 `REPLAY_*` 문서는 중간 실패 기록이며 최신 통과 결과로 해석하지 않는다.

### 최신 실제 재현 결과

| 구분 | E01~E03 기초 자료 분석 | E01~E04 갱신·종료 질문 |
|---|---|---|
| 실제 trace | `709c4aea-4384-4d73-a504-73a705a03768` | `5e47bf4a-55dd-4710-a085-9d05f99858f1` |
| 검증 흐름 | REVISE → PASS | REVISE → REVISE → REVISE |
| 최종 처분 | CAUTIONARY | WITHHELD |
| 실제 검증 모델에 전달된 출처 | 매회 23개 = 문서 3 + 공식 법령 20 | 매회 24개 = 문서 4 + 공식 법령 20 |
| 검색·작성·검증 사이 출처 해시 | 일치 | 일치 |
| 최종 출력 | 검증한 초안과 정확히 동일 | 미통과 초안을 출력하지 않고 183자 보류 안내 |
| 모델 호출 수 | 4회 | 6회 |
| 관측 구간 소요 | 약 104.2초 | 약 120.3초 |

Langfuse의 실제 GENERATION 입력을 다시 읽어 출처 개수를 확인했다. 두 trace 모두 종료되지 않은 SPAN은 없었다. 검색 없이 기존 법령을 재사용한 조건에서도 소요 시간이 길어 지연시간은 별도 개선 대상이다.

기초 분석 답변은 계약 당사자·보증금 3억 원의 최초 지급 방향·등록 기록에 따른 권리 요건·현재 유지에 관한 진술 한계·추가 확인 자료를 설명했다. 최초 제보의 일부 반환 사실을 새로 만들거나 계약 종료를 확정하는 답변과는 달라졌다. 다만 실제 답변 길이는 2,412자로 짧은 상담 답변의 사용성까지 충분히 검증했다고 하지는 않는다.

갱신 질문에서는 시간 순서와 지정 퇴거일을 반영하도록 답변이 개선됐지만, 마지막 검증에서 다음이 남았다.

- 첫 결론 검사에 과도한 차단 가능성이 있다. ‘계약서를 새로 쓰지 않았다는 이유만으로 자동 종료된다고 보기는 어렵다’라는 일반론과 후속 통지에 따른 현재 상태의 조건부 설명을 검증기가 모순으로 처리했다. 첫 문장이 실제 현재 상태를 확정하는 경우와 일반 원칙 소개인 경우를 더 정확히 구분해야 한다.
- 특정일을 적었다는 문서 진술 소개가 `LEGAL_APPLICATION`으로 분류되어 법률 출처 부재로 차단되었다. 사실 소개와 법률 효과 판단의 분류가 아직 안정적이지 않다.
- 제공 법령만으로 특정 통지의 정확한 효력일을 확정할 수 없다는 한계 설명이 `UNCERTAIN` 핵심 법률 판단으로 분류되었다. 불확실성을 공개하는 설명과 근거 없이 효과를 단정하는 주장을 구분하는 개선이 필요하다.

따라서 갱신 질문의 최종 보류를 법제처 접속 실패로 설명해서는 안 된다. 원문은 전달됐고 모델도 호출됐다. 남은 원인은 답변의 조건 적용과 검증의 판정·분류 문제다. 이를 해결했다고 표시하거나 중간 PASS 답변을 골라 최종 결과로 대체하지 않았다.

## 적용 및 한계

- 실행 중인 백엔드가 변경 코드를 다시 로드해야 한다. 기존에 중단된 체크포인트는 이전 모드일 수 있으므로 적용 확인은 새 상담 요청으로 해야 한다.
- 기존 DB Fact의 잘못된 판단 상태를 일괄 수정한 것은 아니다. 새 경로가 그 요약을 사실 원본으로 쓰지 않도록 변경했다.
- OCR/추출 정확성, 대량 문서 처리, 법령 적용 시점 및 법률 해석 전반의 완전성을 보증하지 않는다.
- 이번 사례의 실제 모델 재현 통과만으로 전체 서비스 POC 기준선을 확정하지 않는다.
- 신규·수정 소스에는 한국어 모듈·함수 설명과 상태 전이·원문 흐름·예외 처리 주석을 적용했다. 새 외부 라이브러리가 없어 의존성 파일 변경은 없다.
