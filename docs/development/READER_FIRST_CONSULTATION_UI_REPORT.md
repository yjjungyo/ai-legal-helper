# 상담 UI 개편 — Reader-first Consultation v1 (2026-11-01)

## 화면 캡처에서 확인한 문제
- 완료 후에도 녹색 6단계 처리 내역이 화면의 큰 부분을 점유함. 진행 중 상태로 시작하면 `useState(!completedMode)`가 true를 유지하여 완료 후 자동 접기가 되지 않음.
- 질문의 답변보다 시스템 상태·출처 연결 주장 집계가 더 눈에 띔.
- 핵심 답변, 일반 문단, 인용 근거가 서로 다른 카드 스타일과 과도한 여백으로 끊어져 보임.
- 스크롤 컨테이너 안의 sticky '최신 메시지' 버튼이 답변 문장 위에 떠서 내용을 가림.
- [E01_파일명.pdf] 단독 줄을 섹션 제목으로 오인하는 렌더링 버그가 있음.

## 이번 변경
1. 상담 진행 중이거나 승인 대기 중인 경우에만 진행 상태 카드를 먼저 표시.
2. 완료 후에는 답변 하단의 `<details>` '상담 처리 과정 확인'으로 처리 이력 이동; 기본 닫힘, 단계 상태를 임의로 COMPLETED로 바꾸지 않음.
3. VerifiedPresentationView의 근거 연결 주장 유형은 출력 화면에서 비노출. 백엔드 구조화 데이터와 검증 메타데이터는 그대로 유지.
4. 독서형 본문 스타일 통일(소제목·문단·목록의 간격, 가독성, 결과 강조). 법률 문장·증거명·인용 출처와 복사 기능 유지.
5. sticky '최신 메시지' 버튼 제거. 기존 사용자가 하단에 있을 때만 따라가는 자동 스크롤은 유지.
6. 단독 증거 인용 줄은 제목으로 변환하지 않고 인라인 인용 렌더러로 전달.
7. 진입 시 실제 완료/진행 상태 UI 및 법률 본문 회귀 테스트 추가.

## 테스트 및 배포
GitHub Actions `Presentation Regression`: `npm ci`, `npm run build`, 기존 인용 회귀 테스트 + `consultation-reader-ui.test.cjs` 테스트.

수정은 UI 전용입니다. Verification, LangGraph, 답변 원문과 Snapshot, 증거 결합 데이터, PostgreSQL 마이그레이션은 변경하지 않습니다.
배포된 브라우저 UI는 최신 frontend 빌드를 배포하고 캐시를 갱신해야 적용됩니다.

## 수동 UI 검수
- 민법 제6조 질문: 완료 6단계 대형 카드 없이 답변 결론 → 관련 조문 → 정리 → 하단 처리 이력.
- 완료 후 처리 이력 펼치면 실제 상태 유지; SKIPPED 등 완료로 위장하지 않음.
- 긴 답변 스크롤: 떠 있는 최신 메시지 버튼이 내용을 가리지 않음.
- 증거 인용 클릭: 전체 파일명 및 기존 ID를 이용해 Drawer를 정상 열 수 있음.
- 모바일 375px와 데스크톱 1440px에서 수평 스크롤·클리핑·문장 겹침 확인.
