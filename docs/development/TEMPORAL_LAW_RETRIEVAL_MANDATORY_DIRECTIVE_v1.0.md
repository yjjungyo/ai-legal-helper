# AI Legal Helper — 사건 기준일 기반 법령·조문 검색 의무화 개발 지시서

- 문서 버전: v1.0
- 작성일: 2026-11-05
- 적용 대상: Codex, Antigravity 및 AI Legal Helper 전체 개발
- 상태: 확정 설계 원칙 / 구현 및 검증 필요
- 저장소: `yjjungyo/ai-legal-helper`

## 1. 대전제 (최상위 불변 조건)

**모든 법률 상담에서, 답변 근거로 사용할 법령과 개별 조문은 반드시 해당 쟁점의 사건 기준일에 적용 가능한 버전인지 확인한다.**

이는 최신법령 질문이나 SC-003에 한정되지 않는다. 기존 Vector RAG, 일반 질의, 8개 분야 Agent, Agentic/Adaptive RAG, 재검색, Verification에 동일하게 적용한다.

**최신 조문이 검색되었더라도 사건 당시 적용되지 않았다면, 해당 시점에 유효했던 법령·조문 버전을 재검색하여 사용한다.** 최신 문서를 찾는 것이 목표가 아니라 사건 시점에 적용되는 규범을 찾는 것이 목표다.

## 2. 문제 정의

현행/최신 법령만 검색하거나 의미 유사도만으로 조문을 선정하면, 조문 내용이 사실이어도 사건 시점에는 시행 전이거나 개정 전이어서 잘못된 상담이 발생할 수 있다. 시행일은 답변 마지막에 표시하는 부가 메타데이터가 아니라 **검색 결과 채택 여부를 결정하는 필수 조건**이다.

가상 예: 사건일 2026-11-06, 개정 조문 시행일 2026-12-01이면 2026-11-06 당시 유효한 구 조문을 찾아야 한다. 단, 부칙·경과규정·적용례에 의해 결론이 달라질 수 있으므로 날짜 숫자만 비교하여 단정하지 않는다.

## 3. 공통 처리 흐름

1. **쟁점 및 기준 사건 추출:** LLM이 질문/사실/증거에서 쟁점별 행위 유형과 사건일을 구조화한다. `26.11.06`, `2026년 11월 6일` 등 표현 해석은 LLM 우선. 법령 공포·개정·시행일과 당사자 사건일을 구별한다.
2. **초기 법령 검색:** 기존 Vector RAG와 공식 법령 검색을 사용한다. 벡터 검색 결과도 검증 전에는 최종 근거로 채택하지 않는다.
3. **조문 단위 Temporal Validation:** 법령 ID, 조문 식별자, 버전, 시행 시작·종료, 공포일, 개정 이력, 부칙·적용례·경과규정 등을 공식 출처로 확인한다.
4. **시점 불일치 시 재검색:** 검색된 조문이 사건 기준일에 적용되지 않으면 공식 법령의 연혁/시행 버전에서 해당 기준일에 적용되는 조문을 다시 가져온다. 원래 검색 결과를 그대로 인용하지 않는다.
5. **쟁점별 적용 판정:** 시행일뿐 아니라 사건 유형·적용례·경과규정을 고려하여 `APPLICABLE`, `NOT_APPLICABLE`, `UNCONFIRMED`로 판정한다.
6. **Agent 분석:** 시점 검증을 통과한 조문 및 출처·시행 근거만 확정 근거로 전달한다. 불확실한 근거는 별도 표시한다.
7. **Verification:** 답변의 법적 주장마다 인용 조문이 실제 존재하는지, 해당 사건 기준일에 적용되는지, 주장하는 의무·권리의 근거인지 검사한다. 위반 시 부분 재검색/재생성 또는 안전한 불확실성 표시를 한다.

## 4. 역할 분담

| 구성 | 책임 |
| --- | --- |
| LLM | 날짜 표현·사건 행위·쟁점 의미 추출, 부칙/적용례의 조건 해석 후보 생성 |
| Python | 날짜 유효성, 근거 존재·명백한 모순, 구조 검증, 시행 기간·조건 비교, 결정론적 상태 판정 |
| 공식 법령 소스 | 조문 원문, 법령 식별자, 연혁 버전, 시행일, 부칙, 출처 |
| ChromaDB/Vector RAG | 관련 법령·조문 후보 탐색. 시점 적용성의 최종 판정자가 아님 |
| Law Retrieval Service | 모든 검색 경로에 시점 검증·필요 시 연혁 재검색을 강제 |
| Verification | 조문 실재성, 시점 적용성, 주장-조문 근거 연결성 검증 |

LLM이 해석한 날짜를 다시 4자리 연도 정규식으로 재해석해 차단하지 않는다. 다만 근거가 없거나 세기가 모호하고 확정할 수 없는 경우는 `UNCONFIRMED` 처리한다. 법률 분야·특정 사건·특정 날짜에 맞춘 하드코딩은 금지한다.

## 5. 설계상 필수 예외 및 주의점

- **쟁점별 기준일:** 한 사건의 계약 체결, 갱신, 통지, 퇴거, 위반행위는 서로 다른 기준일을 가질 수 있다. 사건 전체에 단일 날짜를 무조건 적용하지 않는다.
- **사건일 불명확:** 임의로 오늘 날짜를 사건일로 대체하지 않는다. 현재법 기준의 일반 설명인지, 특정 과거 사건의 적용 판단인지 구별하고 필요한 날짜를 질문한다.
- **복수 법령:** 사용자가 명시한 법령과 실제 의무를 규정한 관련 법령이 다를 수 있으므로 쟁점에 맞는 근거를 검색한다.
- **부칙·경과규정:** 개정 조문의 시행일이 도래했더라도 기존 계약에 적용되지 않을 수 있다. 반대로 적용례의 별도 기준일이 있을 수 있다.
- **검색 실패:** 공식 연혁 조문을 확보하지 못하면 최신 조문을 과거 사건에 그대로 적용하지 않는다. 재시도 한도를 두고 `UNCONFIRMED` 및 확인 필요 사유를 반환한다.
- **효율:** 동일 사건·법령·조문·기준일의 검증 결과 캐싱, 중복 LLM 호출 방지, 근거별 선택적 재검색을 적용한다.

## 6. Codex / Antigravity 구현 지시

### A. 먼저 실제 호출 경로를 추적한다

- 일반 RAG, Vector RAG, 분야 Agent 8개, 공식 법령 검색, Adaptive RAG, Verification의 법령 검색 진입점과 반환 구조를 조사한다.
- 현재 `temporal_search_plan.py`, `temporal_resolver.py`, `temporal_verification.py`, `temporal_applicability.py`, `legal_workflow.py` 및 공통 Law Retrieval Service를 우선 확인한다.
- 어떤 경로가 시점 검증을 우회하는지 코드 근거와 함께 정리한다. 기존 P1~P11 기능과 API 호환성을 유지한다.

### B. 공통 검색 계약을 정의한다

검색 결과마다 가능한 범위에서 `law_id`, `article_id`, `source_url`, `version_id`, `effective_from`, `effective_to`, `event_date`, `event_type`, `applicability_status`, `applicability_reason`, `addendum_basis` 및 원문 근거를 전달한다. 필드가 누락되면 임의 값을 채우지 않는다.

### C. 시점 검증 및 재검색을 공통화한다

- Vector/공식 검색 결과를 동일한 Temporal Validation으로 통과시킨다.
- `NOT_APPLICABLE`일 때 사건 기준일에 유효한 연혁 조문을 검색하고 그 조문 자체를 반환한다.
- `UNCONFIRMED`를 `APPLICABLE`로 간주하지 않는다.
- 기존 검색 후보를 폐기할 때에는 이유와 대체 조문 출처를 Trace에 남긴다.
- Agent가 시점 미검증 조문을 확정 근거로 사용하지 못하도록 계약과 Verification을 함께 수정한다.

### D. 관측 및 평가 가능성을 확보한다

Langfuse/로그에 사건 기준일, 쟁점, 원 검색 버전, 검증 상태, 부칙 근거, 재검색 여부, 최종 채택 버전, 소요시간을 추적한다. 법률 내용과 무관한 민감정보는 불필요하게 로깅하지 않는다.

### E. 테스트 케이스를 작성하되 아직 실행하지 않는다

1. 최신 조문이 사건일 이후 시행 → 과거 적용 조문 재검색.
2. 사건일에 최신 조문 적용 가능 → 원 조문 유지.
3. 부칙 적용례에 의해 시행일만으로 판정할 수 없는 경우.
4. 동일 사건에 쟁점별 기준일이 다른 경우.
5. `26.11.06` 등 다양한 날짜 표현.
6. 사건일과 법령 공포일 혼동 방지.
7. Vector RAG 경로에서도 Temporal Validation 필수.
8. 공식 연혁 검색 실패 시 `UNCONFIRMED`.
9. 법령에 존재하지 않는 신고의무 등 주장을 Verification에서 차단.
10. 동일 요청 내 중복 호출·불필요한 지연 방지.

**사용자 지시: 전체 코드 수정이 완료되기 전에는 테스트를 실행하지 않는다.** 테스트 파일 추가와 정적 코드 리뷰는 가능하다. 테스트 실행 시점은 사용자 승인 후 별도 진행한다.

## 7. 완료 기준 (Acceptance Criteria)

- 일반 상담과 모든 Agent 경로에서 시점 검증 우회가 없다.
- 잘못된 시점의 조문이 검색되면 해당 사건 시점의 조문 버전으로 교체된다.
- 부칙·경과규정 미확인 상태에서 적용 가능하다고 단정하지 않는다.
- 답변에서 근거 조문의 버전/시행일/출처를 추적할 수 있다.
- 사건일 불명확·공식 자료 부재 시 안전하게 보류한다.
- 기존 시나리오와 타 분야에 대한 회귀 테스트를 작성한다.
- 코드 변경 사항, 선택한 설계, 대안과 트레이드오프, 미해결 위험, Trace/KPI 측정 방법을 문서화한다.

## 8. 작업 우선순위

**1차:** 실제 검색 호출 경로·우회 경로 조사 → **2차:** 공통 Temporal Validation과 연혁 조문 재검색 → **3차:** Agent/Verification 연결 → **4차:** 테스트 작성·정적 리뷰 → **5차:** 사용자 승인 후 E2E 실행 및 Langfuse 비교.

> 최상위 개발 원칙: **법령을 검색하는 것이 아니라, 사건의 법적 기준일에 실제 적용되는 법령의 해당 조문을 검색한다.**
