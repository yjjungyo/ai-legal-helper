# P0-LAW-01 1단계 — 공식 법령명 후보 식별 독립 모듈

## 목적
검증 LLM이 '부동산 거래신고 등에 관한 법률 시행령'만 추천했더라도 질문의 실제 규율 대상이 '민간임대주택에 관한 특별법 시행령'인지 공식 법령명 목록 검색으로 재확인할 수 있는 독립 기능을 마련한다.

## 이번 커밋
- backend/src/ai_legal_helper/tools/statute_resolver.py
  - 사용자 질문의 긴 내용어로 법제처 lawSearch.do 법령명 목록 조회
  - 공식 반환 법령명, 법령ID, 법령 종류 및 점수와 이유 기록
  - 법령명 식별어, 질문에 명시된 법령 유형과의 일치도를 기준으로 후보 순위화
  - LLM 제안은 확정 후보가 아닌 검색 힌트로 취급
  - 검색 최대 3회, 높은 점수면 조기 종료, 추가 LLM 호출 없음
  - API 키 부재 또는 검색 오류 시 후보 미확정
- backend/tests/unit/test_statute_resolver.py
  - 민간임대사업자 질문과 엉뚱한 LLM 후보를 사용한 회귀 테스트
  - 빈 법령 목록, API 키 부재, 민법 제6조 질문, XML 오류 사례
  - API 응답은 모의 XML로 대체하여 네트워크/LLM 비용 없음

## 로컬 검증
backend 디렉터리에서 다음 실행:
python -m pytest -q tests/unit/test_statute_resolver.py

독립 테스트 결과: 5 passed.
※ 실제 공식 API 통신 및 최종 상담 품질은 아직 검증되지 않았다.

## 운영 연결 전 필수 점검
1. HILT 사용자 승인: 승인받지 않은 추가 법령을 임의 조회하지 말 것. 후보 탐색의 승인 시점과 위치를 정한다.
2. 개인정보: 현재 프로토타입은 질문에서 한국어 내용어를 추출해 외부 API 검색어로 보낼 수 있다. 고유명사 및 주소 유출을 방지하기 위해 로컬 법령명 인덱스 또는 확실한 개인정보 필터를 도입해야 한다.
3. 일반화: 어휘 기반 후보 점수만으로 상위법/하위법 관계와 완전한 의미적 법령 적합성을 보장할 수 없다.
4. 시행일과 부칙: 법령명 확인은 시행일 및 개정 조문의 적용 여부 확인이 아니다. 이를 별도 단계로 구현해야 한다.
5. 속도: 네트워크 호출·캐시·실패 시 지연을 Langfuse로 측정한다.
6. 문서 상담과 일반 상담: 두 HILT 분기, 검색 승인, 재검증까지 통합 검증해야 한다.
7. 기존 SC-001과 민법 조문 검색 회귀 확인.

## 후속 단계
- 개인정보 보호 가능한 공식 법령명 카탈로그 또는 동등한 보호 방안 확정.
- HILT 승인 전 후보 선정을 통합하되 승인 범위를 준수.
- 실제 API 조회로 법령명 및 법령ID를 재검증하고 관련 조문과 부칙 조회 연계.
- 시행일·공포일·적용례를 질문 기준일과 비교.
- 본 질문과 기존 Gold Set A/B 품질·성능 회귀 평가.

※ 이 단계의 코드는 독립 모듈이다. 기존 상담 및 Verification 실행 경로는 변경하지 않았다.
