# 프로젝트 개요

## 프로젝트명

AI 법률도우미(AI Legal Helper)

주택 임대차 분쟁을 대상으로 사건 중심 법률 상담, 증거 분석, 대응계획, 문서 작성까지 지원하는 멀티에이전트 서비스입니다.

## 기술 스택

Frontend는 React + TypeScript, Backend는 FastAPI와 LangGraph 기반으로 구성했습니다.

데이터 계층은 PostgreSQL, Neo4j, ChromaDB를 사용하고 Azure OpenAI, 국가법령정보 API, Langfuse를 연동했습니다.

## 주요 기능

사건 등록, 증거 업로드, 사실 추출·승인, Timeline 구성, 법률 상담, 근거 검증, Next Action 제안, 법률문서 초안 생성 기능을 구현했습니다.

## 기대 효과

법률 비전문가도 자신의 사건과 증거를 바탕으로 권리와 대응 절차를 이해할 수 있도록 지원합니다.

초기 사건 정리와 법률 정보 탐색 부담을 줄이고, 후속 상담까지 이어지는 연속적 사건 관리 기반을 제공합니다.

# 서비스 아키텍처

## 사용자 인터페이스

React + TypeScript 웹 UI에서 사건 생성, 증거 등록, 상담 결과 확인, 법률문서 초안 확인을 담당합니다.

## API 및 오케스트레이션

FastAPI가 요청을 수신하고 LangGraph Supervisor가 상담 워크플로우를 제어합니다.

## Agent 계층

Supervisor는 전체 흐름을 조정하고 Router는 법률 분야를 분류하며 Specialist, Synthesizer, Verification, Re-analysis Agent가 역할을 분담합니다.

## 데이터 저장소

PostgreSQL은 사건·증거·사실·상담 이력을 저장하고 Neo4j는 증거 관계 그래프를, ChromaDB는 법령 벡터 검색을 담당합니다.

## 외부 연동 및 관측

Azure OpenAI는 답변 생성과 검증에 사용되며 국가법령정보 API는 공식 법령 보강에 활용됩니다. Langfuse는 실행 추적과 비용 관측을 담당합니다.

## 핵심 데이터 흐름

1. 사용자가 사건 설명과 증거를 입력하면 FastAPI가 요청을 접수합니다.

2. Supervisor가 사건 맥락과 이전 상담 이력을 조회하고 Router가 질문 유형과 법률 분야를 분류합니다.

3. Specialist Agent가 ChromaDB, PostgreSQL, Neo4j를 활용해 법령과 사건 근거를 수집합니다.

4. Synthesizer가 답변 초안을 생성하고 Verification Agent가 증거 일치성, 법률 근거, 시행일 적용 여부를 검증합니다.

5. 근거가 부족하면 HITL 승인 후 공식 법령 검색과 재분석을 수행하고, 통과 시 최종 답변과 후속 조치를 제공합니다.


# 핵심 기능 및 Agent 구현 내용

## 핵심 기능

### 사건 이해 및 구조화

사건 설명과 증거에서 계약 사실, 당사자, 금액, 날짜를 추출하고 승인된 사실만 Timeline과 사건 컨텍스트에 반영했습니다.

### 법률 근거 검색

ChromaDB 기반 Legal RAG와 PostgreSQL·Neo4j 조회를 결합해 사건 사실과 관련 법령·증거를 함께 탐색하도록 구성했습니다.

### 멀티에이전트 상담 생성

Supervisor- Router- Specialist- Synthesizer 구조로 질문 분류, 분석, 종합답변 생성을 분리했습니다.

### 검증 및 재분석

Verification Agent와 Temporal Verification Gate로 근거 부족, 시행일 오류, 상충 증거를 점검하고 필요 시 공식 법령 검색 후 재분석하도록 구현했습니다.

### 대표 구현 결과

SC-001 시나리오에서 상담 진행 화면, 법령 검색 승인 UI, 최종 답변, Langfuse Trace까지 확인하며 E2E 흐름을 검증했습니다.

## 사용 기술/라이브러리

* LangGraph — 멀티에이전트 상태 기반 워크플로우 제어

* LangChain — Tool 연동, 프롬프트 구성, RAG 파이프라인 구성

* FastAPI — 상담 API 및 백엔드 서비스 구현

* React + TypeScript — 사건 중심 웹 UI 구현

* PostgreSQL — 사건, 증거, 사실, 상담 이력 저장

* Neo4j — 증거·사실·쟁점 관계 그래프 탐색

* ChromaDB — 법령 벡터 검색 저장소

* Azure OpenAI — 답변 생성, 검증, 재분석 모델 호출

* Langfuse — Trace, 토큰, 비용 모니터링

* 국가법령정보 API — 공식 법령 원문 보강 검색

# 기술 문제 해결 과정

## 주요 문제 사례

### 환각 및 근거 불일치

1. 문제 상황 — LLM이 증거와 무관한 사실이나 확인되지 않은 법률 결론을 생성했습니다.

2. 원인 — 생성 단계와 검증 단계가 분리되지 않아 법률 근거와 사건 사실의 정합성이 약했습니다.

3. 해결 방법 — Verification Agent를 두고 Claim 단위 근거 검증, 사용자 승인 증거 기반 처리, 판단 유보 로직을 적용했습니다.

4. 결과 — 근거 중심 답변 구조를 확보했고 미검증 판단의 직접 노출을 줄였습니다.

### 시행일·부칙 적용 오류

1. 문제 상황 — 개정 법령의 공포일과 시행일을 혼동해 실제 적용되지 않는 조문을 답변에 사용할 위험이 있었습니다.

2. 원인 — 최신 법령 검색만으로는 시점별 적용 여부와 부칙 해석이 보장되지 않았습니다.

3. 해결 방법 — 공식 법령 검색, Temporal Verification Gate, 계약 체결일과 시행일 비교 로직을 도입했습니다.

4. 결과 — SC-003 시나리오에서 조문 시행일과 적용 여부를 구분하는 검증 구조를 마련했습니다.

### 중복 거래 및 상충 증거

1. 문제 상황 — 동일 거래가 여러 증거에 기록되어 반환금을 중복 합산하거나 상충 사실을 잘못 판단할 수 있었습니다.

2. 원인 — 증거 요약 결과만 사용할 경우 거래 식별 정보와 원문 맥락이 누락되었습니다.

3. 해결 방법 — 거래 일자, 금액, 식별정보를 함께 대조하고 GraphRAG 요약을 확정 근거로 쓰지 않도록 제한했습니다.

4. 결과 — 실제 반환금과 당사자 주장 금액을 구분하고 잔액 계산의 신뢰성을 높였습니다.

### 응답 지연과 비용 증가

1. 문제 상황 — 반복 검색과 검증·재작성 루프로 응답시간이 길고 비용이 크게 증가했습니다.

2. 원인 — 중복 LLM 호출, 동일 근거 재검증, 변화 없는 재작성 루프가 병목이었습니다.

3. 해결 방법 — Fast-Path, 검증 결과 재사용, 재시도 제한, Early Exit, Local-First Retrieval을 적용했습니다.

4. 결과 — 평균 응답시간 4.32배 개선, 토큰 66.4% 절감, 비용 71.6% 절감을 달성했습니다.

* 법령·판례 근거 정확도와 필수 대응절차 완성도 보강

* 대응계획과 법률문서 워크플로우를 실제 업무 절차 수준으로 확장
