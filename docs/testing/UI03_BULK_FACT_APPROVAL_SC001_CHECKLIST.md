# UI-03 추출 사실 일괄 승인 검증 시나리오

## 목적
SC-001에서 증거별 사실 추출 후 다건 승인이 개별 승인과 동일한 저장/그래프 반영을 수행하는지 확인한다. 프런트엔드 CI 통과는 실제 DB 검증을 대체하지 않는다.

## 준비
- 테스트 전용 사건과 테스트 전용 PostgreSQL/Neo4j 인스턴스 사용.
- SC-001 첫 번째 상담에 필요한 시점의 증거만 업로드한다. 이후 2·3회 상담에서도 각 시점에 해당하는 증거만 추가한다.
- 승인 전 사건 ID, 증거 ID, Claim ID, review_status, Fact 개수, EvidenceLink 개수, CaseRevision 최신 버전을 기록한다.
- Neo4j 동기화는 비동기일 수 있으므로 큐 처리 완료 여부와 실패 로그를 별도로 확인한다.

## 테스트
1. 첫 번째 증거에서 사실을 추출하고 승인 대기 목록이 나타나는지 확인한다.
2. 전체 선택 → 선택 사실 일괄 승인 → 확인을 누른다. 승인 건수와 결과 메시지를 확인한다.
3. PostgreSQL에서 해당 Claim들이 APPROVED이고 EvidenceReview와 CaseRevision이 건별로 남는지 확인한다.
4. 승인된 Claim마다 Fact 및 SUPPORTS EvidenceLink 연결이 있는지 확인한다. 동일 내용의 Fact가 중복 생성되지 않는지 확인한다.
5. Neo4j 동기화 작업 완료 후 승인된 사실/증거 관계가 조회되는지 확인한다.
6. 일부 Claim을 먼저 개별 승인·반려한 뒤 일괄 승인한다. 대기 상태만 선택 가능한지 확인한다.
7. 1건을 의도적으로 실패시키는 테스트 환경에서 부분 성공 결과 및 재시도 가능 여부를 확인한다.
8. 승인 직후 기존 상담 답변에 증거 변경 안내가 표시되고, 재상담 시 새 사실이 반영되는지 확인한다.
9. SC-001 두 번째·세 번째 증거를 순서대로 추가하고 동일 검증을 반복한다.

## 합격 기준
- 선택한 PENDING Claim만 승인된다.
- 승인 건수 = APPROVED 전환 건수; 실패 건은 승인된 것으로 표시되지 않는다.
- 각 성공 건의 EvidenceReview, CaseRevision, Fact, EvidenceLink가 정상 생성/연결된다.
- 그래프 동기화 작업 완료 후 Neo4j 관계가 PostgreSQL 상태와 일치한다.
- 기존 상담 로직과 증거 출처/Span 정보가 유지된다.
