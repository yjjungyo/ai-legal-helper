# ADR-006: 사건 영속성 관리를 위한 SQLite 도입 (Case Persistence)

## 1. 배경 (Context)
P2.2 단계에서는 AI Legal Helper가 일회성 질의응답을 넘어, 사용자의 사건(사실관계, 타임라인, 당사자, 법률 쟁점 등)을 구조화하고 영속적으로 관리하는 기능을 목표로 한다.
이를 위해서는 관계형 데이터를 안정적으로 저장할 수 있는 데이터베이스가 필요하다.

## 2. 대안 (Alternatives)
- **A. 인메모리 저장소 (Python Dict)**: 구현은 빠르나 서버 재시작 시 데이터가 유실된다.
- **B. 파일 기반 저장소 (JSON)**: 간단하지만 관계형 데이터(사건-사실-당사자) 검색과 동시성 처리가 어렵다.
- **C. SQLite**: 서버리스 단일 파일 데이터베이스로, RDBMS의 장점을 유지하면서 설정이 간단하고 로컬 환경에서 격리된 관리가 가능하다.
- **D. PostgreSQL/MySQL**: 엔터프라이즈 환경에 적합하나, 추가적인 인프라 설정(Docker 등)이 필요하여 제약 조건에 위배된다.

## 3. 결정 (Decision)
**대안 C (SQLite)**를 선택한다.

- SQLAlchemy ORM을 사용하여 향후 필요 시 다른 RDBMS로 쉽게 마이그레이션할 수 있는 구조를 채택한다.
- 데이터베이스 파일은 `storage/cases.db`에 저장하여 프로젝트를 오염시키지 않도록 관리한다.
- 사실 변경 이력(`CaseRevision`)과 트랜잭션을 적용해 업데이트 중 오류 발생 시 롤백되도록 안전성을 보장한다.

## 4. 결과 (Consequences)
- **장점**: 별도 서버 띄우기 없이 가볍고 안전하게 사건 및 관련 엔터티의 관계를 관리할 수 있다.
- **단점**: 다중 사용자 접속 시의 동시성 성능에는 한계가 있으나, 현재 로컬/단일 사용자 기반 테스트 환경에서는 충분하다. SQLite 쓰기 락 문제가 발생하면 WAL(Write-Ahead Logging) 모드를 활성화하여 보완할 수 있다.
